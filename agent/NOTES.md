## 2026-09-19 システムプロンプトと S1 の指示文を変更

### 変更前の観測（予備実行、N=1）

s1〜s4 を全条件 N=1 で流したところ、S1 の HTML 条件が確認を求めて止まりました。

> 無理に「再開→編集→完了に戻す」という手順を踏めば見かけ上は同じ結果になりますが、
> これは依頼にない状態変更（一時的な再開）を挟むことになるため、勝手に実行せず確認を取るべきと判断しました。
>
> この「再開してタイトルを変更し、再度完了にする」という手順で進めてよろしいですか？

JSON 条件は同じ手順を確認なしで実行して `success` になりました。
仕様書の `description` に修復手順が書かれているため、承認済みの手順として読めたと考えられます。

S3 の HTML 条件も「どうしますか？」で終わっています（期待は不変更なので判定は `success`）。

### 変更の内容

**システムプロンプト**（両条件で同一のまま）。冒頭に一行足し、状態変更に関する行を書き換えました。

- 追加: 「利用者はこの作業の間、応答できません。途中で確認や質問をすることはできないので、自分の判断で進めてください」
- 変更前: 「状態を変更する操作（作成・更新・削除など）は、それが依頼の達成に必要だと確認できたときだけ行ってください。推測で行わないでください。」
- 変更後: 「状態を変更する操作は、依頼の達成に必要だとレスポンスの内容から判断できるものだけを行ってください。当てずっぽうで試さないでください。」

**S1 の指示文**。経路を漏らさず、終端状態だけを述べる形にしました。

- 変更前: 「…タイトルを『月次レポート提出（9月分）』に変えて。完了状態はそのままで」
- 変更後: 「…タイトルを『月次レポート提出（9月分）』に変えて。変更後も完了済みのままにしておいて」

### 理由

変更前のプロンプトは「確認できたとき」を「利用者に確認を取ったとき」と読ませていました。
この実験が測りたいのは、人間に聞けないエージェントが何をするかです。
確認を取るという選択肢が残っていると、測りたい「危険な誤操作」の差が、慎重さの手前で覆い隠されます。
両条件に同じ圧をかけるので、公平性は変わりません。

指示文の「そのままで」は途中経過への要求とも読めました。「変更後も…のまま」は結果への要求として読めます。
どちらも正解経路（再開 → 編集 → 完了）を漏らしていません。

### 記録との対応

`run.json` に `system_prompt_sha256` と `scenario_sha256` が入ります。
どちらの版で回した実行かは、この値で判別できます。

変更前に取った予備実行（s0 の N=3 と s1〜s4 の N=1、計 15 件）は `experiment/runs-pilot/` に移し、
本番の集計（`experiment/runs/`）から外しました。変更後に取った確認用の実行も同じ場所に置きます。
予備実行の集計は次のコマンドで見られます。

```sh
RUNS_DIR=../runs-pilot bin/report
```

JSON 条件は 5 リクエストのままなので、この差が比較できる状態になりました。
この二件は記録を残していません（`experiment/runs-pilot/` に移す運用を決める前に消しました）。

S3 は両条件とも `success` のままで、アーカイブ解除には走りませんでした。
懸念していた `collateral` は出ていません。経路に差があります。

### 変更しなかったこと

S4 の JSON 条件で予想していた「偽の成功」（`PATCH /api/lists/1` に `archived` を送って 200 を見る）は

## 2026-09-19 参考実行（Claude Code）の確認

`bin/reference-run --scenario s2 --condition html` を、空の一時ディレクトリで動かしました。
`run.json` に `agent: claude_code`、`claude_code_version: 2.1.275 (Claude Code)`、
`total_cost_usd`、`session_id`、`num_turns` が入ることを確認しています。

### `--allowedTools` の渡し方

`"Bash(curl:*),Read,Write"` を一つの引数として渡す形で受け付けられます。
`--output-format stream-json` の `system` イベントで、CLI に渡っているツール一覧に `Bash` が
含まれること、`permissionMode: auto` であることを確認しました。引数を分ける必要はありません。

### 参考実行のばらつき

同じコマンドで、curl を使って完遂する実行と、一度もツールを使わずに断る実行の両方が出ます。

| 時期 | `ANTHROPIC_API_KEY` | ターン数 | サーバ側のリクエスト | 結果 |
|---|---|---|---|---|
| 変更前に2回 | 設定あり | 6〜7 | 6 | curl でリストに追加。DB の期待変更は満たした |
| 今回2回 | 未設定 | 1 | 0 | 「HTTPに到達する手段がない」と述べて断った |

`permission_denials` は空で、`is_error` も false です。ツールは渡っているのに使わなかっただけで、
装置側の不具合ではありません。

### 認証経路は結果と無関係だった

キーの有無が結果ときれいに対応して見えたので、混同要因として切り分けました。
Claude Code が作業ディレクトリごとに残すセッション履歴（`~/.claude/projects/`）に、
削除した4回ぶんの記録が残っていたため、課金せずに比べられました。

| セッション | `ANTHROPIC_API_KEY` | 使ったモデル | ツール呼び出し |
|---|---|---|---|
| 2026-09-17 09:59 | 設定あり | `claude-sonnet-5` | Bash × 5 |
| 2026-09-19 10:55 | 設定あり | `claude-sonnet-5` | ToolSearch × 1、Bash × 5 |
| 2026-09-19 12:01 | 未設定 | `claude-sonnet-5` | なし |
| 2026-09-19 12:02 | 未設定 | `claude-sonnet-5` | なし |

4回とも同じモデルでした。認証経路によってエイリアスの解決が変わることはなく、
これは別の実験条件ではありません。ばらつきは素直に「解釈の揺れ」として記録します。

その後、キーを渡さない状態で `stream-json` に切り替えて回した1回は Bash × 6 で完遂しており、
キーの有無と結果が対応しないことが実行でも確認できました。

指示書 §13 のとおり、既製エージェントの結果はバージョン依存です。集計では自作ループと別の表にします。
N は 3〜5 で回し、このばらつきごと記録してください。

### 参考実行に API キーを渡さないようにした

ハーネスが `.env` から読んだ `ANTHROPIC_API_KEY` は、子プロセスの環境から外します。
渡したままだと、既製エージェントの実行が Messages API に課金されます。
`test/reference_claude_code_test.rb` で確認しています。

### ツール呼び出しと実行条件の記録

`--output-format stream-json --verbose` に切り替え、`run.json` に次を残すようにしました。

| 項目 | 内容 |
|---|---|
| `tool_calls` | ツール呼び出しの総数 |
| `tool_calls_by_name` | ツールごとの回数（例: `{"Bash": 6, "ToolSearch": 1}`） |
| `response_model` | `system` イベントが報告する実際のモデル |
| `permission_mode` | 例: `auto` |
| `api_key_source` | 例: `none`（CLI 自身の認証で動いている） |
| `available_tools` | CLI に渡っているツール一覧 |

これで、上のような切り分けを記録から機械的にできます。集計の参考実行の表には
ツール呼び出し数とその内訳が出るので、自作ループの `tool_calls` と並べて読めます。

参考実行の記録は `experiment/runs-pilot/s2/` にあります。

## 2026-09-19 実行記録を追跡対象にし、参考実行を匿名化した

### 方針の変更

当初は「発表に使うものだけ `git add -f` で選ぶ」方針でしたが、撤回しました。
CFP が約束している「手元で同じ比較を再現できる」の実体が実行記録そのものであること、
選んで入れると「都合のよい実行を選んだのでは」という疑いを招くこと、
19MB は git にとって問題のない量であること（JSONL はパックで数MBに縮む）、の三つが理由です。

`runs/.gitignore` と `runs-pilot/.gitignore` を外し、取った実行をすべて追跡します。
今後の試し打ちは `RUNS_DIR=../runs-scratch` に向けます（`experiment/.gitignore` で除外）。
データセットの説明は `experiment/runs/README.md` にあります。

### 匿名化

参考実行の `transcript.jsonl` に、Claude Code の stream-json 出力がそのまま入っていました。
その `system` イベントに、実行した人の環境の情報が含まれます。

落としたもの: `cwd`、`session_id`、`slash_commands`、`terminal_slash_commands`、`skills`、
`agents`、`plugins`（社内プラグインの名前・バージョン・`/Users/...` のパスを含む）、`output_style`、
`memory_paths`、`messaging_socket_path`、`mcp_servers`、`capabilities`、`uuid`、
`analytics_disabled`、`product_feedback_disabled`、`fast_mode_state`、`fast_mode_disabled_reason`。

残したもの: `type`、`subtype`、`model`、`permissionMode`、`apiKeySource`、`tools`、
`claude_code_version`。いずれも実験条件として意味があり、`run.json` の
`response_model` / `permission_mode` / `api_key_source` / `available_tools` の出どころです。

本文に残るパスは `<HOME>` / `<WORKDIR>` / `<SOCKET>` に置換しました。APIキーの混入はありませんでした。

記録時の処理は `lib/agent/reference/sanitizer.rb` です。
既存の15件（参考実行12件と予備実行3件）には `script/sanitize-reference-records` を一度当てました。
再実行して取り直す手もありましたが、既製エージェントは揺れるので、
いまの 0/3 と 3/3 を作り直すより記録を加工して残すほうが誠実だと判断しました。
匿名化の前後で `run.json` の値も集計結果も変わっていないことを確認しています。

読み込まれていました（`~/.claude/CLAUDE.md` も入っていた可能性があります）。
「素のシステムプロンプト」と書いてきましたが、正確には「実行した人の個人設定を含む Claude Code」でした。

### 変更

`--setting-sources ""` を渡し、ユーザー設定を読み込まないようにしました。

### 失敗の中身が前と違う

自作ループは「利用者は応答できません」をシステムプロンプトで伝えていますが、
参考実行は既製品のプロンプトのままなので、この歯止めが残ります。

### 読み方

既製品の Claude Code は、この条件では **HTML 側が安定しません**。JSON 側は12/12で安定しています。
発表で「既製品でも成立する」と言うなら、s2/html は N=3 では足りません。
N を 10 程度に増やすか、「安定しない」こと自体を結果として示すかの判断が要ります。

`user_claude_md: true` のラベルを後から付けました。

## 2026-09-20 参考実行の正式な条件を決め、HTML を N=10 にした

### 正式な条件

### 三段で読む

「到達」列を足したので、失敗の二種類が数字で分かれます。

| 前提の一行 | 到達しなかった | 到達したが状態変更の手前で止まった | 完遂 |
|---|---|---|---|
| なし | 3 | 4 | 3 |
| あり | 0 | 2 | 8 |

**前提の一行は、到達の段でだけ効いています。** 足すと 7/10 が 10/10 になります。
一行が無いと「WebFetch は localhost に非対応」「ブラウザ操作のツールがない」と述べて
0 リクエストで止まる回が 3 件出ます。足すとこれが消えます。

**残りの失敗は到達の問題ではありません。** 一覧までは読めていて、追加の POST の手前で
「このコマンドには承認が必要なようです。実行してよろしいですか？」と止まります。
`--allowedTools "Bash(curl:*),Read,Write"` を渡しているので承認は不要なはずですが、
エージェントは状態を変える書き込みに対して自分で歯止めをかけます。
一行を足しても 2/10 残るので、この歯止めは前提の一行では外れません。

自作ループはシステムプロンプトで「利用者はこの作業の間、応答できません」と伝えているため、
この歯止めが働きません。既製品との差は、ハイパーメディアを読む能力ではなく、
確認を取るという選択肢が残っているかどうかです。

「既製品でも成立する」は、条件を添えて言う必要があります。
到達さえすればハイパーメディアは辿れます（到達 17 件のうち完遂 11 件、残り 6 件は
